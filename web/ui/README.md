# suri-controller-web

The management web UI of suri-controller. It is built into `../dist`, which
the Go package `web` embeds (`go:embed`) and serves at the mount point of
`web.Handler` (`/` in `cmd/suri-controller`).

Stack: Vite, React, TypeScript (strict), Mantine 8, TanStack Query,
react-router (hash routing), Connect (`@connectrpc/connect-web`) with
protobuf-es v2, and CodeMirror 6 (loaded on demand).

## Commands

```sh
npm ci              # install the exact versions from package-lock.json
npm run dev         # dev server with /api proxied to a running controller
npm run build       # typecheck, then build into ../dist
npm run typecheck   # tsc --noEmit (app and vite config)
npm run gen         # regenerate src/gen from ../../proto (needs protoc)
```

`npm run build` does not need protoc: the generated TypeScript in `src/gen/`
is committed.

## Development

Start a controller on plain HTTP. `SURICONTROLLER_INSECURE_COOKIE=1` lets the
browser keep the session cookie over HTTP:

```sh
# from the repository root
SURICONTROLLER_DATA_DIR=/tmp/suri-dev SURICONTROLLER_LISTEN=127.0.0.1:8080 \
SURICONTROLLER_ADMIN_PASSWORD=admin SURICONTROLLER_INSECURE_COOKIE=1 \
SURICONTROLLER_ET_OPEN=false go run ./cmd/suri-controller
```

Then start the Vite dev server. It proxies `/api` (including the `TailLog`
stream and log downloads) to `SURICONTROLLER_URL`, which defaults to
`http://127.0.0.1:8080`:

```sh
cd web/ui
SURICONTROLLER_URL=http://127.0.0.1:8080 npm run dev
# open http://localhost:5173/ and sign in as admin
```

To test the embedded build, run `npm run build` and rebuild the Go binary
(`go build ./cmd/suri-controller`).

## Regenerating the protobuf code

`scripts/gen-proto-ts.sh` runs protoc with `@bufbuild/protoc-gen-es` (a dev
dependency, so run `npm ci` first) and writes messages and service
descriptors into `src/gen/`:

```sh
PROTOC=/path/to/protoc ../../scripts/gen-proto-ts.sh   # or: npm run gen
```

Commit the regenerated files under `src/gen/` together with the proto change.

## Mounting and API location

- Hash routing (`#/nodes/...`) and Vite `base: './'` keep every URL relative,
  so the UI works under any path prefix (e.g. `/suri/`).
- The API is called at `./api` relative to the page. When the Go handler is
  created with `web.Options{APIBase: "/suri/api"}`, it injects
  `<meta name="suricontroller-api" content="/suri/api">` into `index.html`,
  and the UI uses that base instead. Log downloads use
  `{apiBase}/logs/download?node=<id>&path=<path>`.
- Authentication is the session cookie set by `AuthService.Login`. Any call
  that fails with `unauthenticated` sends the user to the login page.

## Layout

```
index.html            entry page (keep the literal <head> tag: web.go injects the meta after it)
public/               copied as-is (favicon, theme-init.js, .keep for web/dist)
src/main.tsx          providers (Mantine, Query, modals, notifications) and router
src/router.tsx        hash routes, pages are lazy-loaded
src/api/              Connect transport and clients, query client, error helpers, shared hooks
src/components/       layout, auth guard, editors (FileEditor, CodeEditor), diff viewer, commit history, badges
src/pages/            Dashboard, Nodes, NodeDetail (+ node/), Rules, Config, Deploy, Logs (+ logs/), System
src/lib/              formatting, enum labels, log policy helpers, file templates
src/gen/              generated by protoc-gen-es (do not edit)
```
